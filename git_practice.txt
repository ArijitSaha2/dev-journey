Git Practice File

GIT NOTES

1) BASIC GIT WORKFLOW

git status
Shows the current state of the working directory and staging area.

git add <file>
Stages a file for the next commit.

git commit -m "message"
Creates a commit containing the staged changes.
-m stands for message.

git diff
Shows changes that have been made but are not staged.

git restore <file>
Discards unstaged changes and restores the file to its last committed version.

git restore --staged <file>
Removes a file from staging while keeping its changes.

git add .
Stages all changed and untracked files in the current repository for the next commit.
It does not re-commit unchanged files.

git push
Uploads local commits to the remote GitHub repository.
Working: push → local → GitHub

git fetch
Downloads information about changes from the remote repository without applying them.

git pull
Downloads changes from the remote repository and updates the current local branch using its upstream branch.
Working: pull → GitHub → local

2) .gitignore

.gitignore

A .gitignore file tells Git which files and directories should not be tracked.

Common Python entries:
__pycache__/
*.pyc
.env

.gitignore can ignore files, file patterns, and directories.

3) GIT HISTORY

git log
Shows the commit history of the repository.

git log --oneline --decorate -3
Shows the latest 3 commits in a shorter format.
--oneline → Shows each commit on one line.
--decorate → Shows branch/HEAD information next to commits.
-3 → Shows the latest 3 commits.

Related Git log information:
- HEAD → Shows the branch/commit you are currently on.
- origin/HEAD → Points to the default branch of the remote repository.

git show <commit>
Shows the details and changes made by a specific commit.

4) GIT BRANCHES

A branch is a separate line of development.
Creating a branch does not create a duplicate folder or project.

git branch
Lists the branches in the repository.

git branch -r
Lists the remote-tracking branches.

git switch -c <branch>
Creates a new branch and switches to it.

git switch <branch>
Switches to an existing branch.

Changes and commits made on one branch do not automatically appear on another branch.

Local and remote branches:
- main → The local main branch.
- origin/main → A local remote-tracking reference for the remote (GitHub) main branch.
- practice → The local practice branch.
- origin/practice → A local remote-tracking reference for the remote (GitHub) practice branch.
- origin/HEAD → Shows which branch is the default branch on GitHub.

Upstream branches:
- An upstream branch is the remote branch that a local branch tracks.
- Example: main → tracks origin/main.
- Example: practice → tracks origin/practice.

git push -u origin <branch>
git push --set-upstream origin <branch>

Pushes a new local branch to GitHub and sets it as the upstream branch.
-u is the short form of --set-upstream.

After an upstream branch is set, git push can be used normally.

Comparing branches:
git diff main..practice
Shows the differences in file contents between the main and practice branches.
git log main..practice
Shows commits that exist on practice but not on main.

5) GIT PULL REQUESTS

Pull Request (PR):
A request to merge changes from one branch into another.
A PR does not merge the branches automatically.

Example:
practice → main

Create pull request:
Creates a normal PR that is ready for review.

Draft pull request:
Creates a PR that is not ready to be merged yet.
It can later be marked as ready for review.

6) MERGING BRANCHES

git merge <branch>
Merges the specified branch into the current branch.

Example:
While on practice:
git merge main

This merges main into practice.
It does not merge practice into main.

Merge conflicts:
A merge conflict happens when Git cannot automatically combine changes from different branches, usually because both branches modified the same part of a file.

During a conflict:
<<<<<<< HEAD → Current branch's changes.
======= → Separates the two versions.
>>>>>>> main → Incoming branch's changes.

Conflict resolution:
- Choose the changes to keep or combine them manually.
- Remove the conflict markers.
- Save the file.
- git add <file> → Marks the conflict as resolved.
- git commit → Completes the merge and creates a merge commit.

git merge --abort
Cancels the current merge and returns the branch to its state before the merge started.

A merge commit records that two branches were combined.

After resolving and committing a merge locally:
git push
Uploads the updated branch and its merge commit to GitHub.

If a branch is ahead of and behind another branch:
- Ahead → it has commits the other branch does not have.
- Behind → the other branch has commits this branch does not have.
- This means the branches have diverged.

GitHub can show "Compare & pull request" when a branch contains changes that are not in the target branch.

7) BRANCH CLEANUP

git branch -d <branch>
Deletes a local branch safely.
-d safely deletes the branch when its commits have been merged into another branch.

git push origin --delete <branch>
Deletes the branch from the remote (GitHub).

Deleting a branch does not delete commits that are already part of another branch's history, such as main.

Local branch and remote branch are separate:
- git branch -d <branch> → deletes local branch.
- git push origin --delete <branch> → deletes remote/GitHub branch.

8) UNDOING COMMITS

git revert <commit>
Creates a new commit that undoes the changes made by an older commit.
The old commit stays in the history.

Example:
git revert 586642c

Revert is useful when you want to undo a committed change while keeping the history intact.

git reset <commit> or git reset --mixed <commit>
Moves the current branch back to an earlier commit.
Moves the branch back while keeping the changes from the later commits unstaged.
This is the default behavior of git reset.

git reset --soft <commit>
Moves the branch back while keeping the changes from the later commits staged.

git reset --hard <commit>
Moves the branch back and throws away the changes from the later commits.

Reset can be used to move back multiple commits, including all the way to an earlier commit.

Important:
- revert → keeps the old commit and creates a new commit to undo it.
- reset → moves the branch back and removes the later commits from the branch's current history.

Do not casually use reset on commits that have already been pushed to a shared remote branch because it rewrites history.

9) GIT STASH NOTES

git stash
Temporarily saves uncommitted changes so the working tree can be clean.

git stash pop
Restores the most recently stashed changes.

git stash list
Lists saved stashes.
